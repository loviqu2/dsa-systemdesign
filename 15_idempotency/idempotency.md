Idempotency = an operation is idempotent if performing it multiple times has no side effect at all
No idempotency = lets say you want to trasnfer 100$, if you did it 5 times, then you trasnfer 500. 
- but if you check your account balance 5 times in a short time (assuming no other transaction has been made), the result is still the same. This is idempotency.

So how do we fix problems where connection is lost in the middle while a transfer happens?
We introduce an idempotency key. 

##
The client can generate unique keys every time a logical operation is attempted, and reuses that key for every retry on the same attempt. The server then uses a hash map, of key --> result; on a repeat key, and return the stored result instead of reprocessing. 

O(1) algorithm, the key must be generated by client instead of server, as server has no idea where the request came from, and mix-up issues will be caused.
